# codelab:适配stm32f407开发板

## 一、概述

本文介绍如何在 RoboMaster C 型开发板（下面以“ C 板”代称）上进行 openvela 的适配，并且讲述一下我们 openvela 的应用启动，本教程适配的板级外设只支持板上自带的 LED 。主要内容包括：

1. 开发环境的搭建
2. 代码结构
3. 启动流程简述
4. 代码实现
5. 总结

> RoboMaster C 型开发板的主控为`stm32f407igh6`，`stm32f407ig`系列芯片 NuttX 官方已经进行过适配。本教程只是讲解 RoboMaster C 型开发板的 board 层级的适配。

## 四、适配说明

### 适配说明

进行适配之前，我们需要学习[openvela 架构](https://github.com/open-vela/docs/blob/dev/README_zh-cn.md#技术架构)。本篇适配文档主要阐述 openvela 的 board 适配。如何在C板上启动一个 openvela 系统，目前实现了 nsh、led 、botton 功能。整个适配过程实际上是给已经写好的框架提供接口，因此本篇文档主要内容是讲解 openvela 框架，告诉大家整个适配需要提供什么接口。为了保证大家能熟悉适配过程，我们需要理解 openvela 的启动流程。

### 启动流程

接下来简要说明为了完成系统的启动我们要提供哪些函数。[启动流程](./../device_dev_guide/kernel/boot_process.md)中详细说明了板级的初始化流程，具体细节请参考该文档的启动流程图进行学习。

我们需要提前了解 `boardctl` 函数，此函数在板级初始化会调用`board_app_init`、`board_app_finalinit`。

为了让 C 板成功运行 openvela 系统，我们需要提供以下函数：

```C
void stm32_boardinitialize(void)          //由__start中调用，每个STM32芯片都必须提供该函数。  
void board_late_initialize(void)          //执行板级主要驱动的初始化。依赖 CONFIG_BOARD_LATE_INITIALIZE 。
int board_app_initialize(uintptr_t arg)   //由boardctl(BOARDIOC_INIT, 0)调用。
/* 
如果配置 CONFIG_BOARD_LATE_INITIALIZE 选项，由 board_late_initialize() 调用。
如果没有配置 CONFIG_BOARD_LATE_INITIALIZE 选项，由 board_app_initialize(arg) 调用。
在stm32_bringup()函数里将实现驱动的初始化。
*/
int stm32_bringup(void)
```

由于系统启动过程中会调用 `board_autoled` 相关函数，所以我们需要提供以下函数（如果不想提供相关函数，我们需要手动关闭 `ARCH_LEDS` 配置）：

```C
void board_autoled_initialize(void)         //配置 LED 的 GPIO 为输出模式。
void board_autoled_on(int led)              //配置不同状态 LED 的亮
void board_autoled_off(int led)             //配置不同状态 LED 的灭
```

为了完整实现 `stm32_rcc.h`、`stm32_sdio.h`、`stm32.h` 配置，我们需要在 `board.h` 中配置对应的宏，以配置时钟树和对应外设引脚和设备功能。

时钟树配置（这里只展示时钟树配置注释）：

```C
/* Clocking *****************************************************************/

/*   System Clock source           : PLL (HSE)
 *   SYSCLK(Hz)                    : 168000000    Determined by PLL
 *                                                 configuration
 *   HCLK(Hz)                      : 168000000    (STM32_RCC_CFGR_HPRE)
 *   AHB Prescaler                 : 1            (STM32_RCC_CFGR_HPRE)
 *   APB1 Prescaler                : 4            (STM32_RCC_CFGR_PPRE1)
 *   APB2 Prescaler                : 2            (STM32_RCC_CFGR_PPRE2)
 *   HSE Frequency(Hz)             : 12000000     (STM32_BOARD_XTAL)
 *   PLLM                          : 25           (STM32_PLLCFG_PLLM)
 *   PLLN                          : 336          (STM32_PLLCFG_PLLN)
 *   PLLP                          : 2            (STM32_PLLCFG_PLLP)
 *   PLLQ                          : 7            (STM32_PLLCFG_PLLQ)
 *   Main regulator output voltage : Scale1 mode  Needed for high speed
 *                                                SYSCLK
 *   Flash Latency(WS)             : 5
 *   Prefetch Buffer               : OFF
 *   Instruction cache             : ON
 *   Data cache                    : ON
 *   Require 48MHz for USB OTG FS, : Enabled
 *   SDIO and RNG clock
 */

/* HSI - 12 MHz RC factory-trimmed
 * LSI - 32 KHz RC
 * HSE - On-board crystal frequency is 12MHz
 * LSE - 32.768 kHz
 */
```

## 五、代码实现

### src 

#### `stm32_appinit.c`

在 `stm32_appinit.c` 中，我们主要实现 `int board_app_initialize(uintptr_t arg)` 函数，如果打开 `CONFIG_BOARD_LATE_INITIALIZE` ，`stm32_bringup()` 将由 `board_late_initialize()` 调用。如果没有，`board_app_initialize(arg)` 将调用 `stm32_bringup()` 。

```C
int board_app_initialize(uintptr_t arg)
{
#ifdef CONFIG_BOARD_LATE_INITIALIZE
  /* Board initialization already performed by board_late_initialize() */

  return OK;
#else
  /* Perform board-specific initialization */

  return stm32_bringup();
#endif
}
```

#### `stm32_boot.c`

```C
void stm32_boardinitialize(void)
{
#ifdef CONFIG_ARCH_LEDS
  /* Configure on-board LEDs if LED support has been selected. */  

  board_autoled_initialize();
#endif
}


#ifdef CONFIG_BOARD_LATE_INITIALIZE
void board_late_initialize(void)
{
  /* Perform board-specific initialization */

  stm32_bringup();
}
#endif
```

#### `stm32_bringup.c`

```C
int stm32_bringup(void)
{
  int ret = OK;

#ifdef CONFIG_USERLED
  /* Register the LED driver */

  ret = userled_lower_initialize("/dev/userleds");
  if (ret < 0)
    {
      syslog(LOG_ERR, "ERROR: userled_lower_initialize() failed: %d\n", ret);
    }
#endif

  return ret;
}
```

#### `stm32_autoleds.c`

`stm32_autoleds.c` 主要也是实现 LED 的亮灭控制，但和 `stm32_userleds.c` 不同，他主要在系统启动过程中被调用。

```C
/****************************************************************************
 * Private Functions
 ****************************************************************************/

static inline void set_led(bool v)
{
  ledinfo("Turn LED %s\n", v? "on":"off");
  stm32_gpiowrite(GPIO_LEDR, v);
  stm32_gpiowrite(GPIO_LEDG, v);
  stm32_gpiowrite(GPIO_LEDB, v);
}

/****************************************************************************
 * Public Functions
 ****************************************************************************/
#ifdef CONFIG_ARCH_LEDS
void board_autoled_initialize(void)
{
  /* Configure LED GPIO for output */

  stm32_configgpio(GPIO_LEDR);
  stm32_configgpio(GPIO_LEDG);
  stm32_configgpio(GPIO_LEDB);
}

void board_autoled_on(int led)
{
  ledinfo("board_autoled_on(%d)\n", led);

  switch (led)
    {
    case LED_STARTED:
    case LED_HEAPALLOCATE:
      /* As the board provides only one soft controllable LED, we simply
       * turn it on when the board boots.
       */

      set_led(true);
      break;

    case LED_PANIC:

      /* For panic state, the LED is blinking */

      set_led(true);
      break;
    }
}

void board_autoled_off(int led)
{
  switch (led)
    {
    case LED_PANIC:

      /* For panic state, the LED is blinking */

      set_led(false);
      break;
    }
}

#endif /* CONFIG_ARCH_LEDS */
```

#### `stm32_userleds.c`

如果我们想要使用 APP 层的 `EXAMPLES_LEDS`，或者我们想直接使用 `nuttx/drivers/leds`目录下的对应 LED 驱动函数接口，我们需要在 `stm32_userleds.c` 中添加下列函数：

```C
uint32_t board_userled_initialize(void);    
void board_userled(int led, bool ledon);    
void board_userled_all(uint32_t ledset);    
```

`userled_lower.c` 通过调用上面函数接口，提供 `userled_lowerhalf_s g_userled_lower` 给 `userled_upper.c` 以实现下面 led 驱动接口：

```C
static int     userled_open(FAR struct file *filep);
static int     userled_close(FAR struct file *filep);
static ssize_t userled_write(FAR struct file *filep, FAR const char *buffer,
                        size_t buflen);
static int     userled_ioctl(FAR struct file *filep, int cmd,
                         unsigned long arg);
```

具体实现：

```C
#ifndef CONFIG_ARCH_LEDS

/****************************************************************************
 * Private Data
 ****************************************************************************/
static const uint32_t g_ledcfg[BOARD_NLEDS] =
{
  GPIO_LEDB,
  GPIO_LEDG,
  GPIO_LEDR
};

/****************************************************************************
 * Public Functions
 ****************************************************************************/

uint32_t board_userled_initialize(void)
{
  int i;

  /* Configure LED GPIOs for output */

  for (i = 0; i < BOARD_NLEDS; i++)
    {
      stm32_configgpio(g_ledcfg[i]);
    }

  return BOARD_NLEDS;
}

void board_userled(int led, bool ledon)
{
  if ((unsigned)led < BOARD_NLEDS)
    {
      stm32_gpiowrite(g_ledcfg[led], ledon);
    }
}

void board_userled_all(uint32_t ledset)
{
  int i;

  /* Configure LED GPIOs for output */

  for (i = 0; i < BOARD_NLEDS; i++)
    {
      stm32_gpiowrite(g_ledcfg[i], (ledset & (1 << i)) != 0);
    }
}

#endif /* !CONFIG_ARCH_LEDS */
```

#### `stm32f407-robomaster.h`

`stm32f407-robomaster.h`中配置了对应的板级外设的对应管脚的初始化。

```C
/* Configuration ************************************************************/

/* LED.  User LEDR: the red LED is a user LED connected to board LED D12
 * corresponding to MCU I/O PH10.
 *       User LEDG: the green LED is a user LED connected to board LED D12
 * corresponding to MCU I/O PH11.
 *       User LEDB: the blue LED is a user LED connected to board LED D12
 * corresponding to MCU I/O PH13.
 *
 * - When the I/O is HIGH value, the LED is on.
 * - When the I/O is LOW, the LED is off.
 */

#define GPIO_LEDB \
(GPIO_PORTH | GPIO_PIN10 | GPIO_OUTPUT_SET | GPIO_OUTPUT | GPIO_PULLUP | \
 GPIO_SPEED_50MHz)

#define GPIO_LEDG \
(GPIO_PORTH | GPIO_PIN11 | GPIO_OUTPUT_SET | GPIO_OUTPUT | GPIO_PULLUP | \
 GPIO_SPEED_50MHz)
 
#define GPIO_LEDR \
(GPIO_PORTH | GPIO_PIN12 | GPIO_OUTPUT_SET | GPIO_OUTPUT | GPIO_PULLUP | \
 GPIO_SPEED_50MHz)

 /* Buttons
 *
 * B1 USER: the user button is connected to the I/O PA0 of the STM32
 * microcontroller.
 */

#define MIN_IRQBUTTON   BUTTON_USER
#define MAX_IRQBUTTON   BUTTON_USER
#define NUM_IRQBUTTONS  (BUTTON_USER + 1)

#define GPIO_BTN_USER \
  (GPIO_INPUT |GPIO_PULLUP |GPIO_EXTI | GPIO_PORTA | GPIO_PIN0)
```

### Kconfig

添加完对应的函数接口不代表我们彻底完工了，openvela 使用 `Kconfig` 来管理项目配置，因此我们需要添加我们开发板对应的 `Kconfig` 才能完成适配。

```
nuttx/boards/Kconfig
```

接下来我们在 `nuttx/boards/Kconfig` 中添加以下对应的 `Kconfig` 。

配置对应 `board` 的 `Kconfig` ：

```Plain
config ARCH_BOARD_STM32F407_RM
    bool "STM32F407IGH6 ARM Development Board"    
    depends on ARCH_CHIP_STM32F407IG
    select ARCH_HAVE_LEDS
    select ARCH_HAVE_BUTTONS
    select ARCH_HAVE_IRQBUTTONS
    ---help---
        A configuration for the STM32F407 RoboMaster development board.
```

在 `ARCH_BOARD` 中添加默认配置。

如果我们打开的是对应 `board` 配置， `ARCH_BOARD` 的默认值将为 `stm32f407-robomaster` 

```Plain
config ARCH_BOARD
    string
    default "stm32f407-robomaster"      if ARCH_BOARD_STM32F407_RM  
```

最后，为了保证我们 `stm32f407-robomaster/Kconfig` 目录下的 `Kconfig` 被调用，我们需要在最后添加下面配置：

```Plain
if ARCH_BOARD_STM32F407_RM
source "boards/arm/stm32/stm32f407-robomaster/Kconfig"
endif
stm32f407-robomaster/Kconfig
```

由于目前我们不需要添加对应的 `Kconfig` ，因此下面的 `Kconfig` 只做占位使用，方面后期添加功能。

```Plain
#
# For a description of the syntax of this configuration file,
# see the file kconfig-language.txt in the NuttX tools repository.
#

if ARCH_BOARD_STM32F407_RM

endif # ARCH_BOARD_STM32F407_RM
```

### defconfig

1. `defconfig` 是系统配置的最小集合，用于指定默认的基本配置项。因此为了实现系统功能，我们需要在 `config` 目录下添加对应的 `defconfig` 。

如果想要修改配置我们需要使用 `menuconfig` 打开对应配置。详细知识可以学习 [Kconfig 使用指南](https://github.com/open-vela/docs/blob/37d18c33583c4c786e74353d342085ae23a71057/zh-cn/device_dev_guide/build/Kconfig.md) 。
