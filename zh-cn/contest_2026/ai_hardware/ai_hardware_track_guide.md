# AI 硬件产品创新赛道详细指引

## 一、赛道概述

### 1、赛题说明

基于 openvela + ai_agent，开发一个「能主动、会执行」的嵌入式 AI Agent 应用。

### 2、赛题背景

AI Agent 正在从云端走向端侧。但大部分端侧 AI 应用仍是「被动问答」模式——你问它才答，不问就静默。

ai_agent 是运行在 openvela 嵌入式系统上的 AI Agent 框架，专为手表、眼镜、音箱等小型设备设计。它的核心差异化在于：

- **主动任务机制**：Agent 不等用户开口，根据时间和条件主动推送
- **Router 意图路由**：区分「记一下」vs「提醒我」vs「总结一下」，智能分流
- **Tool/Shell 调用**：读传感器、写文件、发通知、执行命令——Agent 能动手
- **自然语言→结构化输出**：语音输入自动解析为待办/日程/备忘
- **多渠道 + 多设备协作**：飞书、微信、语音、MQTT、Node 协议

本次大赛要求参赛者基于 ai_agent 框架，开发一个**真正发挥「主动+执行」能力**的嵌入式应用，而不是又一个聊天机器人。

### 2、应用开发模式

开发 AI 应用有两种参考模式（不限于此，可自由发挥）：

**模式 A：基于设备的通信协议和云端大模型，独立开发 AI 场景应用**

- 适合：熟悉 LLM 云端通信以及设备端通信协议的使用
- 参考实现：[ai_chat demo](../../../../../../packages_demos/tree/dev-ai-contest-2026/ai_chat)

**模式 B：基于 ai_agent 框架开发 LVGL 应用或快应用**

- 创建独立的 LVGL 应用或快应用，通过 ai_agent 的消息总线交互
- 适合：了解 agent 开发、需要更灵活的 LLM 调用和丰富的工具扩展能力
- 参考实现：[mini-memo 应用开发指引](./mini_memo_guide.md)（LVGL 应用）+ [快应用调用 ai_agent](../quickapp/quickapp_velaclaw.md)（快应用）

## 三、赛题要求

### 1、基础要求

#### 让 Agent 在硬件设备上跑起来

- 编译 openvela + ai_agent 固件，烧录到指定硬件
- 配置 LLM 后端，确保基础对话功能正常
- 至少接入一个交互渠道（CLI / 语音 / WebSocket 均可）

#### 开发至少 1 个自定义 Skill

- Skill 是 ai_agent 的扩展能力，定义 Agent 在特定场景下的行为
- Skill 以 Markdown 文件形式存放在 `/data/agent/skills/` 目录
- 需提供 Skill 的使用演示

> 💡 Skill 示例：`weather`（天气查询）、`daily-briefing`（每日简报）、`reminder`（定时提醒）、`news-digest`（新闻摘要）

#### 实现至少 1 个「主动+执行」场景

这是本赛题的核心区分点——你的 Agent 不能只会被动回答问题，必须展示**主动能力**：

| 主动类型   | 说明                 | 示例                              |
| ---------- | -------------------- | --------------------------------- |
| 定时主动   | 按时间周期主动推送   | 每早 8 点推送天气和日程           |
| 阈值主动   | 满足条件时主动告警   | 心率超过 120 自动提醒             |
| 事件主动   | 检测到变化时主动通知 | 检测到新消息主动播报              |
| 上下文主动 | 基于历史记忆主动建议 | 连续 3 天没运动，主动建议出门走走 |

#### 交付完整的应用场景说明

- 用户故事：谁在什么场景下使用，解决什么问题
- 功能清单：列出实现的全部功能
- 技术实现：说明使用了 ai_agent 的哪些核心能力

### 2、进阶要求（加分项）

#### 端云/端端协作

- 设备端 Agent 与电脑端 Agent 配合完成复杂任务
- 需体现任务拆分：端侧做什么、云侧做什么、如何通信
- 示例：电脑端 Claude 生成代码 → 设备端 Agent 执行测试 → 结果回传

#### 记忆机制

- 设计轻量记忆方案，支持跨会话上下文延续
- 展示记忆实际效果（记住用户偏好、持续学习等）
- 需考虑端侧存储受限的场景

#### 智能家居/设备互联

- 接入智能家居生态
- 通过 Agent 意图理解实现智能控制
- 展示与 Skill 体系的联动
- 开发独立的 LVGL 应用，提供自定义 UI 交互

### 3、不属于本赛题范围

- ❌ 纯云端应用（不运行在 openvela 设备上的不算）
- ❌ 纯对话机器人（没有主动能力、没有工具调用的不算）

## 五、提交代码

组委会会为每支队伍创建专属的 GitHub 代码仓库（命名 `contest2026_<编号>_<队伍名>`，默认 public）。AI 硬件作品（LVGL 应用 / Demo、ai_agent 框架能力与自定义 Skill 等）在该专属仓内开发，按**子目录**组织（由 manifest 通过 `<linkfile>` 映射到 openvela 工程对应位置）。比赛期间 **fork 专属仓 → PR → 自行 review 合入**（无需等待组委会审核）。AI Coding 对话会自动记录到本机 staging（不会自动上传），需由你**主动导出/打包**选定会话到仓内 `logs/` 目录（详见 [《AI Coding 日志归集与提交手册》](../ai_coding_log_guide.md)）。完整的仓库获取与提交流程，见 [《参赛代码提交指南》](../code_submission_guide.md)。

> 若需改动 `vendor_<厂商>`（上真机改板级配置 / 加外设驱动）或 `nuttx` 等公共仓，处理方式见 [《参赛代码提交指南》](../code_submission_guide.md)。
