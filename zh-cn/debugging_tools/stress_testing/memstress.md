# memstress 内存压力测试工具

## 一、概述

`memstress` 是一款源自 NuttX-Apps 的内存压力测试工具，专用于对嵌入式系统的内存管理子系统（Memory Management Subsystem）进行高强度压力测试。

在 openvela 等基于 NuttX RTOS 的系统中，您可以使用 `memstress` 来验证内存管理器在高并发和持续动态分配场景下的稳定性和正确性。它能有效帮助开发者提前发现并定位复杂的内存问题，例如：

- **内存损坏 (Memory Corruption)**：内存块被意外写入或覆盖。
- **内存泄漏** **(Memory Leaks)**：已分配内存未能正确释放。
- **非法内存访问 (Illegal Memory Access)**：访问了未分配或已释放的内存区域。
- **数据完整性****问题 (Data Integrity Issues)**：例如位翻转 (Bit-Flips)。

## 二、工作原理

`memstress` 通过维护一个内存节点（Node）数组来模拟复杂的内存使用场景。其核心测试逻辑如下：

1. **初始化**：创建一个指定数量节点的数组，用于追踪所有测试内存块的状态。
2. **循环测试**：工具在一个无限循环中持续执行以下操作：
    - **随机选择**：从数组中随机选择一个节点。
    - **状态判断与操作**：
        - **如果节点未分配内存**：工具会随机执行以下三种内存分配函数之一，分配一个**不大于指定最大值的随机大小**的内存块，并用预设的数据模式填充该内存块。
            - `malloc()`: 标准内存分配。
            - `aligned_alloc()`: 对齐内存分配。
            - `realloc()`: 重新分配内存。
        - **如果节点已分配内存**：工具会执行**数据完整性****校验**，检查内存块中的数据是否与初始填充的数据一致。
            - **若不一致**，表明发生了内存错误。工具将立即打印详细的错误现场信息并触发断言（Assert）以中止测试。
            - **若一致**，工具会随机决定是保留该内存块，还是调用 `free()` 将其释放，以增加内存碎片化，模拟更真实的运行环境。
3. **多线程支持**：当启用多线程模式时，每个线程都会独立维护一套节点数组并执行上述测试循环，从而对内存管理器施加并发压力。

## 三、如何使用 `memstress`

### 步骤 1: 在编译时启用工具

```Makefile
CONFIG_TESTING_MEMORY_STRESS=y
```

### 步骤 2: 执行测试命令  

通过系统 Shell 执行 `memstress` 命令。

#### 命令格式

```Bash
Usage: memstress -m <max_alloc_size> -n <num_nodes> -t <sleep_us> [-x <num_threads>] -d
```

#### **参数说明**

| **参数**              | **说明**                                                                                               | **默认值** |
| :-------------------- | :----------------------------------------------------------------------------------------------------- | :--------- |
| `-m <max_alloc_size>` | **（必需）** 设置单次内存分配的最大尺寸（单位：字节）。工具将在此值范围内随机选择分配大小。            | `8192`     |
| `-n <num_nodes>`      | **（必需）** 设置测试列表中节点的数量。该值决定了并发管理的内存块总数。                                | `1024`     |
| `-t <sleep_us>`       | **（必需）** 设置两次操作之间的延时（单位：微秒）。用于控制测试压力。                                  | `100`      |
| `-x <num_threads>`    | （可选）启用多线程压力测试，并指定线程数量。                                                           | `1`        |
| `-d`                  | （可选）启用调试模式。该模式会大量输出日志，详细记录每次内存分配和释放的操作地址与大小，便于问题分析。 | 未启用     |

#### 使用示例

**场景**：模拟覆盖 10 MiB 内存的压力测试。我们配置 2560 个节点，每个节点最大可申请 4 KiB (4096 字节) 内存，每次操作间隔 100 微秒，并使用单线程。

```Bash
# 执行命令
memstress -m 4096 -n 2560 -t 100 -x 1
```

此命令配置的理论最大内存占用为：4096 字节/节点 * 2560 节点 = 10 MiB。

## 四、重要提示：内存消耗评估

`memstress` 是一个持续运行的测试，只有在检测到错误时才会停止。在运行前，请务必根据以下公式预估其最大潜在内存消耗，确保系统有足够的可用内存。

**注意**：不当的参数配置（特别是 `-m` 和 `-n` 过大）可能导致系统内存被完全耗尽，从而引发系统崩溃或无响应。

**最大内存消耗 ≈** **`max_alloc_size`** **×** **`num_nodes`** **×** **`num_threads`**

请注意，这是理论上的峰值，实际内存使用会因随机的分配和释放而动态变化。建议从较小的参数开始测试，逐步增加压力。
