# 连接服务 XPC 服务端 (Conn XPC Server) API 开发指南

**Conn XPC Server** 模块构成了连接子系统的服务端框架。它通常运行在系统核心的守护进程（Daemon）中，负责统一管理系统的连接能力（Wi-Fi, Bluetooth 等）。

作为 IPC 通信的接收端，该模块的主要职责包括：

- **服务监听**：在指定的 IPC 通道上监听来自上层应用（Clients）的连接请求。
- **请求分发**：接收客户端的消息，根据操作码（OpCode）将其分发至对应的业务处理模块（如 Wi-Fi Manager 或 BT Stack）。
- **状态维护**：维护所有已连接客户端的上下文信息，管理客户端权限及生命周期。
- **事件广播**：当底层硬件状态发生变化时（如搜索到新网络），向所有订阅的客户端广播通知。

## 1. API 接口概览

该模块包含服务端的核心管控逻辑及服务端视角的消息定义。

### 1.1 服务端核心逻辑

`conn_xpc_server.h` 定义了服务端的启动、停止及客户端管理接口。

- **核心功能**：

    - **服务启动 (Start/Stop)**：初始化 IPC 服务端，绑定地址并开始监听。
    - **连接管理**：处理客户端的接入（Accept）与断开（Disconnect），维护连接池。
    - **消息路由**：注册消息处理函数（Handlers），定义如何解析并响应不同类型的请求。

### 1.2 消息处理与定义

`conn_xpc_server_msg.h` 定义了服务端内部处理消息或向客户端发送响应时所需的数据结构。

- **核心功能**：

    - **响应结构体**：定义服务端执行结果的返回格式（如状态码、返回数据载体）。
    - **事件通知结构**：定义服务端主动上报事件（Event）的数据包格式。
    - **内部消息封装**：如果适用，定义服务端内部组件间传递消息的格式。
